# ADR-005：復原提示顯示 5 秒，計時不經 port，以 Jest fake timers 控制

- 狀態：提議
- 日期：2026-10-10
- 決策者：Architect agent / 待人類核准

## 背景

US-09 要求按下「已澆水」後顯示可「復原」的短暫提示，顯示時間由設計決定；「提示消失後紀錄保留」要以可控制的計時器在元件測試驗證，不依賴真實等待。`CLAUDE.md` 規定時間等外部依賴要經過 `packages/core/src/ports/` 的 port。

## 決策

1. 提示顯示 **5 秒**（`tokens.md` 的 `duration.undoSnackbar`）。
2. 紀錄在按下時就寫入儲存；復原是把前一個最後澆水日寫回去。提示消失只是關閉 UI，不觸發任何資料變更。
3. 計時以 `apps/mobile` 中提示元件的 `setTimeout` 實作，**不新增 Timer port**；元件測試以 `jest.useFakeTimers()` 加 `jest.advanceTimersByTime(5000)` 控制。

## 考慮過的選項

顯示時間：

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 5 秒（選定） | 足夠看清訊息並按下復原；Material Design 對含動作的 snackbar 建議 4–10 秒 | 使用螢幕閱讀器時可能偏短 |
| 3 秒 | 不打擾 | 來不及反應，尤其是誤按後才意識到 |
| 10 秒或不自動消失 | 對輔助科技友善 | 長時間遮住清單底部；連續澆多株時一直被提示佔住 |

計時方式：

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| UI 的 `setTimeout` + Jest fake timers（選定） | 最簡單；Jest 的 modern fake timers 完全可控、確定；計時不影響任何領域結果 | 與「時間經過 port」的字面規則不同，需要本 ADR 說明例外 |
| 新增 `Timer` port（由 `FakeClock` 一起推進） | 符合規則字面；core 可測 | core 根本不需要計時（復原與時間無關）；fake 模式 build 的假時鐘不會前進，提示在 e2e 中永遠不消失、會遮住畫面，還要另外設計推進方式 |

## 後果

- 例外的界線：只影響 UI 呈現、不影響領域結果（今天、到期、紀錄內容）的計時與動畫，可以直接使用 `setTimeout`／動畫 API，以 Jest fake timers 測試；凡影響領域結果的時間一律經過 `Clock`。Reviewer 依此界線審查。
- 提示消失、App 被關閉或切到背景時，紀錄都已保留，與計時器是否觸發無關。
- e2e 不等待提示消失（避免真實等待），只驗證提示出現與按下復原；Maestro 在提示出現後立即點擊，5 秒在 CI 模擬器上足夠。
- 同時只保留最新的一個復原機會；舊提示被新提示取代時，舊紀錄保留。
- 若人類希望螢幕閱讀器開啟時延長或不自動消失，可在實作時以 `AccessibilityInfo` 判斷，不影響本設計的其他部分。
