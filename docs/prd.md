# PRD：澆水日記（plant-watering）

> 狀態：已核准（yimingc-1010，2026-10-10；開放問題 Q1–Q9 由人類回答，以人類合併 PRD v1.1 PR 為準）
> 由 PM agent 依 `.claude/skills/pm/SKILL.md` 撰寫；人類核准後才能進入設計階段。
> 產品構想（人類提供）：「記錄家裡植物的澆水。每株植物有自己的澆水間隔，App 告訴我今天要澆哪些，澆完按一下記錄。資料只存在手機上。」
>
> App 顯示名稱（主畫面圖示下的名字）：澆水日記（Q9）

## 問題與目標

家裡養了好幾株植物、每株需要的澆水頻率不同時，很難記得哪一株上次是什麼時候澆的、今天該澆哪幾株，結果不是忘了澆，就是重複澆。這個 App 讓使用者為每株植物設定澆水間隔，打開 App 就看到今天該澆（含已逾期）的植物，澆完按一下就記錄下來；所有資料只存在手機本機。

## 目標使用者

- 在家裡照顧數株到數十株室內或陽台植物的個人，使用自己的一支手機（iOS 或 Android），通常在早上或下班後打開 App 確認今天要澆哪些。

## 名詞與計算規則

以下規則由構想推得或由人類在開放問題中決定，依據列在每條後面；所有 story 的驗收標準都以這些規則為準。

| 名詞 | 定義 | 推論依據 |
| --- | --- | --- |
| 今天 | 依 App 時鐘（測試時為可設定的假時鐘）在裝置本地時區的日曆日期；計算以「日」為單位，不看時、分 | 構想以「今天要澆哪些」描述，是以日為單位的概念；裝置時區改變時（例如出國）就以新的時區計算（Q8） |
| 澆水間隔 | 每株植物各自設定的整數天數，範圍 1–365 | 構想「每株植物有自己的澆水間隔」；以天為單位與「今天」一致；上限 365 天（Q4） |
| 植物名稱 | 去除前後空白後 1–30 個字元；不可與其他植物同名（去除前後空白後完全相同即視為同名） | Q4 |
| 最後澆水日 | 該植物最近一筆澆水紀錄的日期；新增植物時由使用者輸入「上次澆水日」（預設今天，不可晚於今天） | Q1；尚未發生的澆水不能被記錄，所以不可晚於今天 |
| 到期日 | 最後澆水日 + 澆水間隔（天） | 間隔指「兩次澆水之間」的天數，所以從實際澆水那天起算 |
| 待澆 | 今天 ≥ 到期日 | 「今天要澆哪些」應包含今天到期與之前已到期但還沒澆的植物，否則逾期的植物會從畫面上消失 |
| 逾期天數 | 今天 − 到期日（今天到期為 0） | — |

## MVP 範圍

### User stories

每個 story 一個編號，對應 `e2e/` 下檔名以 `us-<NN>-<slug>` 開頭的測試。驗收標準中的日期都以假時鐘設定，不依賴真實時間經過。

#### US-01 新增植物

身為使用者，我想要新增一株植物並設定它的澆水間隔，以便 App 能替它計算澆水日。

驗收標準：

- Given 植物清單為空、今天是 2026-03-05 When 使用者輸入名稱「龜背芋」、澆水間隔 7 天，上次澆水日維持預設並儲存 Then 植物清單出現一筆「龜背芋」，顯示澆水間隔 7 天、最後澆水日 2026-03-05、下次澆水日 2026-03-12
- Given 今天是 2026-03-10 When 使用者新增「龜背芋」，澆水間隔 7 天、上次澆水日 2026-03-01 Then 龜背芋立即出現在今日待澆清單，標示逾期 2 天
- Given 今天是 2026-03-10 When 使用者將上次澆水日設為 2026-03-11 並按儲存 Then 不會新增植物，上次澆水日欄位顯示錯誤狀態
- Given 新增植物畫面 When 名稱為空白（或只有空白字元），或去除前後空白後超過 30 個字元，並按儲存 Then 不會新增植物，名稱欄位顯示錯誤狀態
- Given 已有「龜背芋」 When 使用者新增名稱為「 龜背芋 」（前後有空白）的植物並按儲存 Then 不會新增植物，名稱欄位顯示錯誤狀態，植物清單仍只有一筆龜背芋
- Given 新增植物畫面 When 澆水間隔為空、0、負數、非整數或大於 365 並按儲存 Then 不會新增植物，間隔欄位顯示錯誤狀態
- Given 新增植物畫面 When 澆水間隔為 1 或 365 並按儲存 Then 植物新增成功
- Given 新增植物畫面 When 使用者取消 Then 植物清單內容與新增前相同

#### US-02 查看植物清單

身為使用者，我想要看到我所有的植物和各自下次該澆水的日期，以便掌握整體狀況。

驗收標準：

- Given 已有「龜背芋」（間隔 7 天，最後澆水日 2026-03-01）與「虎尾蘭」（間隔 14 天，最後澆水日 2026-03-01），今天是 2026-03-05 When 使用者開啟植物清單 Then 兩株植物都顯示，龜背芋的下次澆水日為 2026-03-08，虎尾蘭為 2026-03-15，兩者都顯示最後澆水日 2026-03-01
- Given 沒有任何植物 When 使用者開啟植物清單 Then 顯示空狀態，並提供前往新增植物的入口

#### US-03 查看今日待澆清單

身為使用者，我想要打開 App 就看到今天該澆的植物（包含逾期的），以便不漏澆。

驗收標準：

- Given 任何狀態 When 使用者啟動 App Then 第一個畫面是今日待澆清單
- Given 「龜背芋」間隔 7 天、最後澆水日 2026-03-01 When 今天是 2026-03-07 Then 今日待澆清單不包含龜背芋
- Given 同上 When 今天是 2026-03-08 Then 今日待澆清單包含龜背芋，標示為今天到期（逾期 0 天）
- Given 同上 When 今天是 2026-03-11 Then 今日待澆清單包含龜背芋，標示逾期 3 天
- Given 所有植物都未到期（或沒有任何植物） When 使用者開啟今日待澆清單 Then 顯示空狀態
- Given App 在前景顯示今日待澆清單、今天是 2026-03-07，龜背芋到期日為 2026-03-08 When 假時鐘前進到 2026-03-08 且 App 從背景回到前景 Then 今日待澆清單包含龜背芋（以元件測試或單元測試驗證）
- Given 今天是 2026-03-11，「Basil」逾期 0 天、「Monstera」逾期 3 天、「Aloe」逾期 3 天 When 使用者開啟今日待澆清單 Then 由上而下依序為 Aloe、Monstera、Basil（逾期天數多的在前，同逾期天數依名稱排序；Q7）
- 中文名稱的排序規則（例如依注音或筆畫）在設計階段決定。

#### US-04 記錄澆水

身為使用者，我想要澆完水後按一下就記錄，以便 App 重新計算下次澆水日。

驗收標準：

- Given 今天是 2026-03-11，龜背芋（間隔 7 天、最後澆水日 2026-03-01）在今日待澆清單上 When 使用者在該植物上按下「已澆水」 Then 龜背芋從今日待澆清單消失
- Given 同上 When 使用者按下「已澆水」後開啟植物清單 Then 龜背芋的最後澆水日為 2026-03-11，下次澆水日為 2026-03-18（從實際澆水日起算，不是從原到期日 2026-03-08 起算）
- Given 今日待澆清單上有龜背芋與虎尾蘭 When 使用者只對龜背芋按下「已澆水」 Then 虎尾蘭仍在今日待澆清單上，且它的最後澆水日不變

#### US-05 編輯植物

身為使用者，我想要修改植物的名稱和澆水間隔，以便在季節或植物狀況改變時調整。

驗收標準：

- Given 龜背芋間隔 7 天、最後澆水日 2026-03-01 When 使用者將名稱改為「大龜背芋」並儲存 Then 植物清單與今日待澆清單都以新名稱顯示，最後澆水日不變
- Given 龜背芋間隔 7 天、最後澆水日 2026-03-01，今天是 2026-03-05 When 使用者將間隔改為 3 天並儲存 Then 下次澆水日變為 2026-03-04，且龜背芋出現在今日待澆清單，標示逾期 1 天
- Given 編輯畫面 When 名稱不符合規則（空白、超過 30 個字元、與另一株植物同名）或間隔不在 1–365 的整數範圍並按儲存 Then 不會儲存，原本的名稱與間隔不變，對應欄位顯示錯誤狀態
- Given 編輯龜背芋 When 名稱維持「龜背芋」、只修改間隔並儲存 Then 儲存成功（與自己的原名稱相同不算同名）

#### US-06 刪除植物

身為使用者，我想要刪除不再照顧的植物，以便清單只留下需要的植物。

驗收標準：

- Given 植物清單有龜背芋與虎尾蘭 When 使用者對龜背芋選擇刪除並在確認提示中確認 Then 龜背芋從植物清單與今日待澆清單都消失，虎尾蘭不受影響
- Given 同上 When 使用者在確認提示中取消 Then 龜背芋仍在植物清單上，資料不變

#### US-07 資料保存在本機

身為使用者，我想要關掉 App 再打開時資料都還在，以便長期記錄。

驗收標準：

- Given 使用者已新增龜背芋並記錄一次澆水 When 完全關閉 App 後重新啟動（不清除 App 資料） Then 植物清單仍有龜背芋，名稱、澆水間隔、最後澆水日都與關閉前相同
- Given 使用者已刪除一株植物 When 完全關閉 App 後重新啟動 Then 該植物不會再出現

#### US-08 提前記錄澆水

身為使用者，我想要為還沒到期的植物記錄澆水，以便順手澆了之後 App 能從那天重新計算（Q2）。

驗收標準：

- Given 今天是 2026-03-05，龜背芋（間隔 7 天、最後澆水日 2026-03-01）不在今日待澆清單上 When 使用者在植物清單的龜背芋上按下「已澆水」 Then 植物清單中龜背芋的最後澆水日為 2026-03-05、下次澆水日為 2026-03-12
- Given 同上，按下「已澆水」之後 When 今天變為 2026-03-08 Then 今日待澆清單不包含龜背芋（原到期日已被新的紀錄取代）
- Given 龜背芋的最後澆水日已是今天 2026-03-05 When 使用者在植物清單再次按下「已澆水」 Then 最後澆水日仍為 2026-03-05、下次澆水日仍為 2026-03-12

#### US-09 復原誤按的澆水紀錄

身為使用者，我想要在誤按「已澆水」後馬上復原，以便不會弄亂植物的澆水日（Q3）。

驗收標準：

- Given 今天是 2026-03-11，龜背芋（間隔 7 天、最後澆水日 2026-03-01）在今日待澆清單上 When 使用者按下「已澆水」 Then 畫面顯示可按「復原」的提示
- Given 同上，提示仍在顯示 When 使用者按下「復原」 Then 龜背芋回到今日待澆清單並標示逾期 3 天，植物清單中的最後澆水日回到 2026-03-01
- Given 同上 When 提示消失後（未按復原） Then 紀錄保留：最後澆水日為 2026-03-11，龜背芋不在今日待澆清單上（以可控制的計時器在元件測試驗證，不依賴真實等待）
- Given 從植物清單提前記錄澆水（US-08） When 提示仍在顯示時按下「復原」 Then 最後澆水日回到記錄前的值
- 提示的顯示時間在設計階段決定。

### 不做清單

- 推播或本機通知提醒：構想中的「App 告訴我」解讀為打開 App 時顯示今日待澆清單；通知需要權限、背景排程與原生設定，留待 MVP 驗證後再做。
- 植物照片或相機功能。
- 雲端同步、App 自建的雲端備份、匯出與匯入（構想明確要求「資料只存在手機上」）。作業系統層級的備份（iCloud 裝置備份、Android 自動備份）不另外關閉，見非功能需求「資料保存」（Q5）。
- 帳號、登入、多裝置、多人共享同一組植物。
- 澆水歷史的列表或統計圖表（MVP 只顯示最後澆水日與下次澆水日）。
- 修改或刪除過去的澆水紀錄（MVP 只提供記錄後立即復原，見 US-09）。
- 依季節、天氣、植物種類自動調整間隔；植物資料庫或品種建議。
- 施肥、換盆等澆水以外的照護紀錄。
- 桌面小工具（widget）、Apple Watch、平板專屬版面。
- 多語系（MVP 只提供繁體中文，見非功能需求）。

## 非功能需求

| 類別 | 需求 | 驗證方式 |
| --- | --- | --- |
| 效能 | 有 200 株植物時，App 冷啟動後 3 秒內顯示今日待澆清單；按下「已澆水」後 1 秒內清單更新（Q6） | e2e 以 200 株植物的 fixture 啟動 App，對今日待澆清單使用 3000 ms 的等待逾時斷言；記錄澆水後以 1000 ms 逾時斷言清單更新 |
| 離線 | 所有功能在沒有網路時都能使用；App 不傳出任何使用者資料（平台的 EAS Update 更新檢查除外，它不含使用者資料） | `packages/core/src/ports/` 不定義任何網路 port（Reviewer 檢查）；Android e2e 開啟飛航模式後執行 US-03、US-04 的 flow 並通過 |
| 隱私與權限 | 不要求任何敏感權限（定位、相機、相簿、通知、聯絡人）；不含分析、廣告或當機回報等會傳出資料的 SDK；資料只寫入 App 沙盒內的本機儲存 | prebuild 後檢查 iOS `Info.plist` 沒有任何 `NS*UsageDescription`、Android manifest 沒有危險權限（CI 腳本或 Reviewer 檢查）；Reviewer 檢查新增依賴不含分析或追蹤 SDK |
| 資料保存 | 資料在 App 重新啟動與 App 版本更新後保留；解除安裝 App 時資料隨之刪除；不關閉作業系統層級的備份（iCloud 裝置備份、Android 自動備份），App 本身不把資料傳到任何伺服器（Q5） | 重新啟動：US-07 的 e2e；版本更新：預發布人工驗收腳本（`docs/qa/device-test.md`）從前一版升級後確認資料仍在 |
| 無障礙 | 所有可操作元素都有無障礙標籤與角色；觸控目標至少 44×44 pt；系統字級放大到最大時文字不被截斷、操作仍可完成 | 元件測試斷言每個按鈕與輸入欄位的 `accessibilityLabel` 與 `accessibilityRole`；字級放大與螢幕閱讀器操作列入人工驗收腳本 |
| 語言 | 介面文字只提供繁體中文（推論依據：構想以繁體中文提出） | Reviewer 檢查介面字串；元件測試斷言畫面上的固定文字 |
| 正確性 | 名詞與計算規則（到期日、待澆、逾期天數、排序、輸入驗證）集中在 `packages/core`，並以假時鐘測試；包含跨月、跨年、閏年 2 月 29 日與時區改變的情況 | `packages/core` 的 Vitest 單元測試；核心模組覆蓋率 ≥ 80% |
